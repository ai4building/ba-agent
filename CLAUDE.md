## Project Overview

BA-Agent (Building Automation AI Agent) is a cross-language integration system built on J2 Innovations FIN Framework / Haxall. It uses AI to automate building systems across their full lifecycle: HMI auto-generation during engineering, and intelligent alarm diagnostics (FDD), dynamic energy optimization, and virtual inspections during O&M. See `DESIGN.md` for the full architecture specification (in Chinese).

## Technology Stack

- **Middleware:** FIN Framework (commercial platform built on Haxall core) — provides DB Builder, Graphics Builder, Logic Builder application suites. AXON scripting for logic & data orchestration.
- **AI Engine:** Python (LangChain, NumPy, Pydantic, DuckDB)
- **Integration Bridge:** hxPy — containerized Python bridge. Runs Python inside Docker (`ghcr.io/haxall/hxpy:latest`), not in-process. Haxall manages the container lifecycle via `py()`.
- **Frontend (dual-route):**
  - **Ractive.js** — embedded within FIN Graphics Builder for lightweight custom widgets
  - **React SPA** (Vite + TypeScript) — standalone app mounted via FIN WebMod for rich AI interaction UI
- **Python Tooling:** uv (package manager & virtual env)
- **Deployment:** Docker Compose (Haxall/FIN instance). Python runs inside hxPy-managed containers, **not** as a separate Docker service.

## Architecture (Three Layers)

- **`src/baAgentPod/`** 
- — Fantom/AXON plugin layer. AXON functions tagged with `op` are published as Haystack REST API endpoints (custom Ops). Uses Haxall Task engine for persistent background AI agent processes (`taskSend` for async messaging). Connector Tree for BACnet/Modbus device discovery. Direct interaction with building point data via AXON (`curVal`, `hisRead`, Haystack 4 tags). AI write operations go to a staging area (Priority 16) requiring human confirmation. Life-safety points (fire, smoke, emergency power) are strictly read-only.
- **`src/baAgentPy/`** 
- — Python AI code 
- **loaded by hxPy containers** (not an independent service). `main.py` defines `BaAgentService` class, imported via `pyExec()` and invoked via `pyEval()`. LLM orchestration in `core/agent_workflow.py`. Domain engines in `services/`: FDD root cause analysis, energy digital-twin optimization, virtual inspection sensor health scoring, report generation.
- **`src/baAgentUI/`** 
- — Dual frontend approach. 
**Route A:** Ractive.js custom widgets inside FIN Graphics Builder for embedded diagnostics. 
**Route B:** React SPA (chat interface, diagnostic cards, 3D topology fault-path visualization) mounted as external app via FIN WebMod. Both communicate with AI Agent through Haystack Ops or WebSocket.

## hxPy Integration Model

### Runtime Mechanism

Python execution in Haxall is **not** in-process — `py()` starts a Docker container running the `hxpy` Python module. The container communicates with Haxall via IPC. This means:
- Python environment is fully isolated and portable
- Custom Docker images can pre-install heavy AI dependencies (LangChain, PyTorch, etc.)
- Deployable on edge gateways (Linux + Java 17+ + Docker) for offline operation

### Core Functions

| Function | Purpose | BA-Agent Usage |
|----------|---------|----------------|
| `py()` | Create new Python session, specify Docker image & network | Start AI reasoning engine with custom `ba-agent-py` image |
| `pyInit()` | One-time initialization configuration | Load LLM libraries and models at task startup |
| `pyDefine()` | Define variables in the Python session | Pass real-time point data to AI models |
| `pyExec()` | Execute Python code block (declare functions/classes) | Import `BaAgentService` class from `main.py` |
| `pyEval()` | Evaluate Python expression, return result | Get AI decisions (e.g., optimized setpoints, diagnoses) |

### Data Marshalling

hxPy automatically converts between Haystack types and Python types. Critically, **Haystack Grid objects convert directly to `pandas.DataFrame`** — essential for energy analysis and load prediction tasks that process large time-series datasets.

### IO Mount

Haxall mounts the project's `io/` directory to `/io/` inside the container. Python code is placed in `io/` for the container to load. Intermediate files (configs, temp datasets) generated by AXON can be read directly by Python.

### Custom Docker Image

Build a custom image based on `ghcr.io/haxall/hxpy:latest` to pre-install AI dependencies:
```dockerfile
FROM ghcr.io/haxall/hxpy:latest
RUN pip install langchain numpy pandas pydantic duckdb
COPY src/baAgentPy/ /io/baAgentPy/
```

### Session Persistence

Within a Haxall Task context, a `PySession` stays alive across multiple calls. This allows the AI Agent to maintain long-running reasoning processes without restarting the container on each invocation.

## AXON Interface & Task Engine

### Custom Ops (REST API Publishing)

AXON functions tagged with `op` are automatically published as Haystack HTTP API endpoints. Example:
```axon
// Tag: {op, admin}
agentAsk(req) => do
  session: py(image: "ba-agent-py:latest")
  pyExec(session, "from baAgentPy.main import BaAgentService")
  pyDefine(session, {question: req->question})
  pyEval(session, "BaAgentService().ask(question)")
end
```
This exposes `POST /api/agentAsk` as a standard Haystack Op accessible from any HTTP client.

### Task Engine (Persistent Background Agent)

The Haxall Task engine runs AI agents as persistent background tasks:
- Tasks survive restarts and run continuously
- `taskSend` provides async message passing — AI agent processes events without blocking the main Haxall thread
- Ideal for continuous monitoring, alarm correlation, and proactive optimization

### Semantic Orchestration Flow

The standard AI decision loop in AXON:
1. **Context Awareness:** `readAll(air and temp and point)` — query all matching sensors
2. **Feature Engineering:** `hisRead()` + `stats` — trend analysis and data cleaning
3. **AI Decision:** `pyEval()` — send processed data to Python agent, get strategy
4. **Closed-Loop Execution:** `connWrite()` / `invokeAction()` — write decisions back to field controllers

### Security & Authentication

FIN Framework provides:
- **OpenID Connect (SSO)** for user authentication
- **API Token** mechanism for programmatic access to Haystack Ops
- Only authorized users/applications can invoke AI Agent interfaces

## Key Design Constraints

- hxPy container calls are non-blocking from Haxall's perspective (must not impact real-time controller performance)
- All AI recommendations must include explainable reasoning with historical trend evidence
- Core diagnostics must run locally in Docker without public LLM dependency (offline-capable)
- Life-safety systems are never writable by AI

## Business Workflows

### EPC Engineering Deployment

Automated commissioning pipeline:
1. **Auto-Discovery:** Connector Tree discovers BACnet/Modbus devices and their point lists
2. **AI Tagging:** `agentAutoTag()` Op — Python extracts point names and feature values, matches against Haystack 4 semantic model, executes `diff().commit()` to auto-populate the Folio database
3. **Template Binding:** AXON calls Template Wizard API to auto-associate discovered devices with standard graphics and logic templates

### O&M Intelligent Operations

Continuous operations pipeline:
1. **Smart Alarms:** Logic Builder AI monitoring blocks detect anomalies. When rule-based logic is insufficient, data is pumped to Python Agent to identify "soft faults" (sensor drift, system oscillation)
2. **Human-AI Collaboration:** User inputs natural language commands (e.g., "set conference room to energy-saving mode") via HTML5 UI. AI Agent parses semantics and executes `writeVal()` through AXON to modify field setpoints
3. **Predictive Maintenance:** AI Agent reads historical trends, generates load prediction Grids, exposes forecasts through custom Ops for Dashboard Builder to display 24-hour energy consumption alerts

## Development Commands

```bash
# Python (uv) — local development & testing
uv sync                        # Install/sync dependencies
uv run python src/baAgentPy/main.py   # Local debugging only (production runs inside hxPy container)
uv run pytest tests/           # Run all tests
uv run pytest tests/test_xxx.py       # Run single test (preferred for speed)

# Custom hxPy Docker image
docker build -t ba-agent-py:latest -f src/baAgentPy/Dockerfile src/baAgentPy/  # Build custom hxPy image

# Frontend (React/Vite)
cd src/baAgentUI && npm install       # Install dependencies
cd src/baAgentUI && npm run dev       # Dev server
cd src/baAgentUI && npm run build     # Production build
cd src/baAgentUI && npm run type-check # TypeScript type check

# Docker — Haxall/FIN instance
docker compose up              # Start Haxall service
docker compose up --build      # Rebuild & start
docker compose down            # Stop services

# Type checking (run after code changes)
uv run mypy src/baAgentPy/     # Python type check
```
